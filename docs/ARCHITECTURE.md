# Архитектура Flutter-приложения (FSD)

Зависимости направлены вниз: app → pages → widgets → features → entities → shared.
Соседние слайсы одного слоя не импортируют друг друга. Внешний код использует
index.dart слайса; внутренние api/model/ui/lib остаются деталями реализации.

## Расположение кода

- app: запуск, маршруты, тема приложения, сборка зависимостей Riverpod.
- pages: экраны и соединение действий с маршрутами.
- widgets: составные блоки каталога, корзины и индикатора корзины.
- features: авторизация, поиск, добавление в корзину, изменение профиля,
  оформление заказа.
- entities: сессия/хранилище, настройки, каталог, покупатель, заказ.
- shared: транспорт ShopApi, ошибки API, Json, форматирование денег,
  локализация и универсальные элементы интерфейса.

Каждый слайс разделён на api (запросы), model (состояние), ui (виджеты),
lib (функции предметной области). Не создавайте пустые сегменты заранее.

## Запросы и состояние

ShopApi не знает о сущностях или Riverpod-состоянии пользователя. app/providers
передаёт ему язык, признак авторизации и чтение токена. Репозитории каталога,
покупателя и заказа принимают этот транспорт; checkout использует публичный API
сущности order для общих полей и обработки результата.

Новая функциональность добавляется в соответствующий feature, а не в страницу.
Контроллер checkout отвечает за переходы шагов и блокировку повторных запросов.
Отдельные AddressStep/DeliveryStep/ReviewStep отвечают за отображение и ввод.

В API пока используется Json с явными наборами GraphQL-полей. Полная генерация
типизированных ответов GraphQL не входит в этот рефакторинг.

## Переиспользуемый интерфейс

- AsyncContent/RetryView: загрузка, ошибка и повтор.
- AppNetworkImage: изображение с заглушкой.
- PriceText: минимальные денежные единицы Vendure и валюта ответа сервера.
- PaginationBar: постраничная навигация.
- AppBackButton: pop по истории либо переход на родительский маршрут.
- ProductCard и OrderTotals: интерфейс соответствующих сущностей.

shared не читает entities/settings. Общие виджеты получают данные через параметры
или используют стандартные зависимости Flutter (Theme, Localizations).

## Локализация и навигация

Все пользовательские строки находятся в l10n/app_ru.arb, app_en.arb, app_tg.arb.
После изменения запускайте flutter gen-l10n. Сгенерированные файлы в
lib/shared/i18n не редактируются вручную. В UI используйте AppLocalizations.of(context).
Динамические значения передаются через placeholders ARB.

Кнопка назад обязательна на дочерних экранах, в том числе при прямом открытии
маршрута без истории. На главном экране родительского маршрута нет.
Во время подтверждения заказа навигация назад блокируется до завершения запроса.

## Проверки

    flutter gen-l10n
    flutter analyze
    flutter test
    flutter build apk --debug

architecture_test.dart проверяет направление зависимостей и публичные API.
navigation_localization_test.dart проверяет возврат при прямом открытии,
возврат по истории и одинаковые наборы ключей трёх языков.
Тестовые ответы, хранилище и локализованный MaterialApp находятся в test/support.

Для проверки на Windows Android-эмуляторе:

    flutter build apk --debug --target-platform android-x64
