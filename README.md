# LOLO — Flutter

Мобильный клиент для Vendure из C:\Users\user\Desktop\marketplace.

Реализовано: OTP-вход и сессия, русский/таджикский/английский интерфейс,
темы, каталог Shop API, категории, поиск по Enter, постраничная навигация,
обновление жестом, состояния ошибки и пустой выдачи, карточка товара
с фотографиями и выбором варианта, корзина авторизованного покупателя
с добавлением товаров, изменением количества и удалением. Цены Vendure переводятся из минимальных
денежных единиц; валюта берётся из API, без фиктивной конвертации.

## Запуск

Бэкенд из его корневой папки:

    npm run dev:server

Android-эмулятор:

    flutter pub get
    flutter run

Телефон в одной сети с компьютером (подставьте LAN IP компьютера):

    flutter run --dart-define=VENDURE_API_URL=http://192.168.1.10:3000/shop-api

Flutter Web:

    flutter run -d chrome --dart-define=VENDURE_API_URL=http://localhost:3000/shop-api

Канал задаётся через --dart-define=VENDURE_CHANNEL_TOKEN=...
По умолчанию используется __default_channel__.
Для Web бэкенд должен разрешать origin клиента в CORS.
HTTP на Android разрешён только debug-манифестом; для release нужен HTTPS.
URL фотографий должен быть доступен с устройства (localhost сервера на телефоне
не работает); настройте AssetServerPlugin assetUrlPrefix на доступный адрес.

## Следующие этапы

Интеграция реальной оплаты,
оплата и история заказов; сохранённые адреса, отслеживание доставки и страницы продавцов.
Сейчас эти сценарии ещё не реализованы. OTP-бэкенд настроен на devMode
и ConsoleSmsProvider, перед реальным запуском потребуется SMS-провайдер.

Корзина использует activeOrder и сохранённый bearer-токен OTP-сессии.
Добавление доступно после входа; гостевая корзина пока не реализована.
Повторные нажатия блокируются на время обновления. Автоматический повтор
мутаций отключён, чтобы сетевой сбой не добавил товар дважды.


## Оформление заказа

Кнопка в корзине открывает получателя и адрес, затем доступные способы
доставки и проверку итоговой суммы. Подтверждение переводит заказ
в ArrangingPayment и вызывает addPaymentToOrder; успех показывает код заказа.
Текущий сервер использует dummyPaymentHandler: это тест без списания денег.
Перед подключением реального провайдера нужно заменить тестовый сценарий
оплаты на интеграцию платёжного провайдера, включая проверку статуса платежа.
При потере ответа подтверждения повторная отправка блокируется на экране.


## Профиль и заказы

В меню аватара откройте профиль: доступны имя и фамилия, подтверждённый
телефон, настройки и история заказов. Служебный email phone-auth скрывается.
История показывает оформленные заказы, по 10 на страницу, новые сверху;
активная корзина исключена. Карточка заказа содержит состав, статус,
суммы и адрес доставки. Данные загружаются с bearer-токеном пользователя.
Недоступный заказ не отображается; после оформления можно открыть историю.
